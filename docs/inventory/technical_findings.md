# ارزیابی فنی کد موجود

## اعتبار ساختاری

- هر ۱۰ فایل `.ipynb` JSON معتبر با `nbformat 4.5` هستند.
- پنج Notebook پژوهشی kernel ثبت‌شده ندارند؛ پنج Notebook کدنویسی kernel `python3` دارند.
- `aristotle_logic.py` از نظر syntax با `py_compile` سالم است.
- اجرای واقعی کد در محیط پاک متوقف شد، چون وابستگی `networkx` ثبت یا نصب نشده است. `requirements.txt` یا محیط بازتولیدپذیر وجود ندارد.

## رفتار واقعی PoCها

### `SSOC.ipynb:36`

فقط وجود edge از پیش افزوده‌شدهٔ `Whole -> Part` را بررسی می‌کند. استنتاج، یادگیری یا ساخت ابژه از ورودی انجام نمی‌شود.

### `code.ipynb`

- در سلول ۰ همهٔ زوج‌های ورودی به ترتیب لیست، با رابطهٔ `part_of` متصل می‌شوند. معنا از داده استخراج نشده است.
- در سلول‌های ۴ و ۵ روابط `next_to` و «روی» صرفاً به‌صورت قراردادی ساخته می‌شوند.
- تابع جدید `reflect` در سلول ۷ خارج از کلاس تعریف شده و به `SSOC_Minimal` متصل نمی‌شود؛ خروجی سلول ۸ نیز همان `reflect` قدیمی را نشان می‌دهد.
- «مرکزی‌ترین مفهوم» در گراف کامل سه‌گرهی معنی ندارد، چون درجه‌ها برابرند و انتخاب تابع وابسته به ترتیب است.

### `aristotle_logic.py` و `intelegence_core.ipynb`

- parser با regex محدود است و نقش‌نمای فارسی، جمع، فاصله و نفی را درست مدل نمی‌کند.
- الگوی «بعضی ... هستند» قبل از «بعضی ... نیستند» بررسی می‌شود. آزمایش regex نشان داد «بعضی پرندگان پرواز نمی‌کنند» به‌اشتباه affirmative تشخیص داده می‌شود و عبارت «پرواز نمی‌کنند» به‌عنوان predicate مثبت ذخیره می‌شود.
- `DiGraph` تنها یک edge برای هر زوج نگه می‌دارد؛ افزودن quantifier دیگر attribute قبلی را overwrite می‌کند، درحالی‌که `statements` تاریخچهٔ جداگانه دارد. این دو منبع حقیقت ممکن است ناسازگار شوند.
- `check_contradiction` فقط چند زوج quantifier را می‌شناسد، اولین مورد را برمی‌گرداند و همهٔ حالت‌ها/جهت‌ها را پوشش نمی‌دهد.
- کد «منطق ارسطویی کامل» نیست؛ فقط چند فرم جمله و یک زنجیرهٔ بسیار محدود را شبیه‌سازی می‌کند.

### `reflect.ipynb`

- نسخه‌ها بر یک `value_dict` ثابت تکیه دارند؛ meaning همان values دیکشنری است.
- نسخهٔ نهایی هر token ناشناخته، از جمله «در»، «و»، «به»، «دارد»، «هستم» و علامت سؤال را «مفهوم جدید» یاد می‌گیرد. خروجی ثبت‌شدهٔ خود Notebook این خطا را نشان می‌دهد.
- `concept_graph.clear()` حافظهٔ گراف را در ابتدای هر ورودی پاک می‌کند.
- `system_identity` بیرون pipeline باقی می‌ماند و هدف را با رشته‌های تکراری گسترش می‌دهد؛ این state drift است، نه خودآگاهی.
- تشخیص تناقض فقط حالت hard-coded «زندگی/کم‌آبی» را می‌سنجد، آن هم بر edgeای که معمولاً با جهت لازم ساخته نمی‌شود.
- چند خروجی پیشنهادهای تکراری تولید می‌کنند؛ deduplication و ارزیابی کیفیت وجود ندارد.

## سطح بلوغ اجزا

| جزء | سطح فعلی | قابل استفاده مستقیم؟ |
|---|---|---|
| Notebookهای گفتگو | آرشیو خام | بله، فقط به‌عنوان منبع |
| گراف NetworkX | نمایش PoC | نه، نیازمند model/schema |
| parser فارسی | regex نمایشی | نه |
| موتور منطق | subset ناقص | نه، ولی ایدهٔ آزمایش قابل حفظ است |
| contradiction detection | چند شرط ثابت | نه |
| reflection | شمارش/شرط/رشته ثابت | نه |
| self-structuring | افزودن token و edge | نه |
| آزمون | printهای نمونه | نه؛ unit test وجود ندارد |

## نتیجه

کد فعلی برای نشان‌دادن تفاوت «ابژه، رابطه، منطق و بازتاب» مفید است، اما هیچ بخش آن هنوز معیار یک مؤلفهٔ شناختی قابل‌اعتماد را برآورده نمی‌کند. در مرحلهٔ بعد باید ابتدا specification و test cases نوشته شوند و سپس کد از نو، کوچک و مستقل ساخته شود.
